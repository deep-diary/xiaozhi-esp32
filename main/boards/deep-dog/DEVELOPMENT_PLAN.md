# Deep-Dog 开发计划

本文档为机器狗语音控制（前进、后退、跳舞）的**分阶段开发计划**，尽量**仅在本目录（main/boards/deep-dog/）内**完成，减少对主项目其他板型的影响。

---

## 目标

- **语音控制**：通过小智/主项目语音识别 → MCP 工具 → 本板实现的底盘接口，实现「前进」「后退」「跳舞」等。
- **实现方式**：CAN 控制 12 个无刷电机（4 腿×3 关节），不依赖 URDF，关节角规划在本板内完成。

---

## 阶段一：单电机与 CAN 验证

**目标**：确认 CAN 与电机协议可用，能通过 MCP 或本地代码控制单电机。

| 任务 | 负责模块 | 说明 |
|------|----------|------|
| CAN 初始化与引脚 | can + config.h | 使用现有 config.h 中 CAN_TX/RX GPIO，在板级启动时初始化 TWAI |
| 电机协议与 12 电机注册 | motor | 按 dog/README 中 ID 表注册，确保使能/位置指令能发出 |
| 单电机 MCP 测试 | motor | 用现有 motor MCP 工具或临时工具验证单电机运动与限位 |

**完成标准**：至少 1 个电机能通过 MCP 或代码使能并移动到指定角度。

---

## 阶段二：单腿控制

**目标**：一条腿（3 关节）能完成站立位、卧倒、迈一步（前进/后退）。

| 任务 | 负责模块 | 说明 |
|------|----------|------|
| LegControl 类与配置 | leg | 电机 ID、上下限、站立位、步数、腿类型 |
| 站立/卧倒/回站立 | leg | 调用 motor 设置目标位置，限幅在控制上下限内 |
| 正弦步态迈一步 | leg | 当前步数 + 总步数 → 相位 → 关节偏移，叠加到站立位 |
| 与 motor 联调 | leg + motor | 单腿 3 电机同步做一步 |

**完成标准**：单腿能按指令站立、卧倒、向前/向后迈一步。

---

## 阶段三：整机步态

**目标**：4 条腿协同，实现前进、后退、站立、卧倒。

| 任务 | 负责模块 | 说明 |
|------|----------|------|
| DogControl 类 | dog | 持有 4 个 LegControl，初始化时配置各腿 ID/限位/站立位 |
| 初始化/站立/卧倒 | dog | 调用 4 腿对应接口 |
| 前进/后退步序 | dog | 步态相位（如对角步），循环触发各腿迈一步 |
| 与 leg/motor 联调 | dog + leg + motor | 整机前进、后退、停 |

**完成标准**：整机能稳定站立、卧倒，并能连续前进、后退若干步。

---

## 阶段四：语音与 MCP 对接

**目标**：语音说「前进」「后退」「跳舞」时，实际驱动机器狗动作。

| 任务 | 负责模块 | 说明 |
|------|----------|------|
| 板级 MCP 工具改为调用 DogControl | esp_sparkbot_board.cc | go_forward / go_back / dance 等不再调用 SendUartMessage，改为 DogControl 接口 |
| 去掉/禁用 UART 底盘初始化 | esp_sparkbot_board.cc | 机器狗不用 UART 底盘，可注释或条件编译 InitializeEchoUart |
| 语音链路验证 | 主项目 + 本板 | 语音唤醒 → 说「前进」等 → 确认调用对应 MCP 工具并执行动作 |

**完成标准**：语音指令能可靠触发前进、后退、站立、卧倒。

---

## 阶段五：跳舞与扩展

**目标**：实现「跳舞」动作，并可扩展左转/右转等。

| 任务 | 负责模块 | 说明 |
|------|----------|------|
| 跳舞动作序列 | dog + 可选 trajectory | 定义多关键帧或时序，可选用 trajectory 插值平滑 |
| 左转/右转（可选） | dog | 步态上差速或身体偏转 |
| 参数暴露（可选） | dog + MCP | 步幅、速度等通过 MCP 参数调节 |

**完成标准**：语音「跳舞」能触发一段可复现的跳舞动作。

---

## 依赖关系小结

```
can → motor → leg → dog
                  ↘ trajectory（可选，用于平滑/跳舞）
板级 esp_sparkbot_board.cc 只依赖 dog（或直接调 leg/motor 做调试）
```

---

## 注意事项

- **仅改本目录**：新代码与修改尽量限于 `main/boards/deep-dog/`；必须动主项目时只做最小改动（如已有 Kconfig 选项、已有板型分支）。
- **编译**：选择 `CONFIG_BOARD_TYPE_DEEP_DOG` 时，本目录及子目录所有 `.cc`/`.cpp`/`.c` 会被递归加入编译，无需改主 CMakeLists 的源列表。
- **头文件**：include 使用相对路径，如 `#include "dog/dog_control.h"`、`#include "can/ESP32-TWAI-CAN.hpp"`。

各子模块的接口细节与数据结构见对应子目录 README（can、motor、leg、trajectory、dog）。
