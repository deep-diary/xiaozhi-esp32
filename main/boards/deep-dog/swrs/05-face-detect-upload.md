# 05 · 本地人脸检测与图像上传

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 依赖 | 相机可用；后台上传入口（可与 [06](./06-face-recognize-immich.md) 并行定义） |
| 代码落点 | `main/boards/diary-brain/`；可参考同仓库 `deep-dog` / `deep-thumble` 的 ESP-DL 人脸检测经验 |
| 验收 | 约 1Hz 检测；检出人脸后裁剪图到达服务器 |

## 1. 背景

设备侧做**检测（有没有脸）**，不做完整身份识别（交给 Immich，见 [06]）。检出后上传人脸图，供后台识别，并驱动前端 Kiosk 与对话个性化（[07]）。

## 2. 目标

- 每隔约 **1 秒**做一次人脸检测（可配置）。
- 检测到人脸时，上传裁剪后的人脸 JPEG（或整帧 + bbox，见开放问题）。
- 控制上传频率，避免同一人连续刷屏。

## 3. 范围

**包含**

- 本地检测流水线（采帧 → 推理 → 裁剪 → 上传）
- 与推流共存时的降载策略（检测可降分辨率、可与推流分时）
- 上传成功后可选发 MQTT `face/event`（轻量元数据）

**不包含**

- Immich 调用、人物档案、Kiosk（[06][07]）
- 设备侧 1:N 人脸库识别（P1 不做，降低模型与存储压力）

## 4. 架构决策：图怎么传？

| 通道 | 适合 | 不适合 | 结论 |
|------|------|--------|------|
| MQTT Base64 | 小事件、控制 | 大图、QoS/带宽差 | **事件走 MQTT，图不走 MQTT** |
| HTTP POST multipart | 二进制 JPEG、易鉴权 | 需后台服务常驻 | **推荐：内网 HTTP 上传** |
| 直传 Immich | 少一跳 | 设备持 Immich Key 风险高、耦合紧 | 不推荐设备直连 |

推荐链路：

```text
设备 --HTTP POST JPEG--> DeepDiary 后台 --识别--> Immich
     --MQTT face/event--> EMQX（可选，仅通知「已上传 / upload_id」）
```

## 5. 检测与降载策略

| 项 | 建议值 | 说明 |
|----|--------|------|
| 检测周期 | 1000 ms | 与原始需求一致 |
| 输入分辨率 | 240×240 或更低 | 对齐 LCD/检测模型；可与推流分辨率解耦 |
| 同人去抖 | 同一 bbox/特征冷却 10–30s | 避免 1Hz 重复上传 |
| 无人脸 | 不上传 | 仅打 debug 日志 |
| 多人脸 | P1：取最大脸或分数最高一张 | 多人策略可后续扩展 |

参考：仓库内 `deep-dog/face_ai`、`deep-thumble` 人脸文档（组件版本、误检踩坑）。

## 6. 上传 API 草案（后台，供联调）

`POST /api/diary-brain/faces`

- Headers：`Authorization` / 设备 token；`X-Device-Id`
- Body：`multipart/form-data`，字段 `image`（JPEG）、可选 `detected_at`、`bbox`
- Response：`{ "upload_id": "...", "accepted": true }`

设备在 MQTT `face/event` 中可带：

```json
{
  "upload_id": "…",
  "bbox": [x, y, w, h],
  "ts": 1710000000
}
```

## 7. 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| DET-01 | 周期检测 | 默认 1s，可配置 |
| DET-02 | 检出上传 | 有人脸则裁剪上传；失败重试有上限 |
| DET-03 | 去抖 | 冷却期内不重复上传 |
| DET-04 | 资源友好 | 与语音/推流冲突时降低检测频率或暂停检测 |
| DET-05 | 可开关 | MQTT 或 NVS 可关闭检测（省电/隐私） |
| DET-06 | 隐私 | 日志不落完整人脸图；外网不裸传 |

## 8. 验收标准

- [ ] 镜头对人脸约 1s 内触发上传；服务器收到可打开的 JPEG
- [ ] 无人脸时无上传风暴
- [ ] 同一人持续出镜时，上传次数受冷却限制
- [ ] 关闭检测开关后停止推理与上传
- [ ] 开启推流时检测仍可用，或明确降级策略并文档化
